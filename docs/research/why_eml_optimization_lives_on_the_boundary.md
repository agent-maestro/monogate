# Why EML Optimization Lives on the Boundary

Date: 2026-05-26

Status: public research note draft

## Claim

The high-dimensional geometry story is not decorative. It is the reason EML
tree search becomes strange so quickly.

A complete depth-`k` EML tree starts with `2^k` terminal coordinates. Before
the optimizer has even evaluated the first internal node, it is already moving
through a high-dimensional cube. In that geometry, the center becomes a tiny
event and the boundary dominates.

The classical warning sign is:

```text
V(unit_ball_d) / V([-1,1]^d) -> 0
```

The Monogate high-D packets show the same pressure in EML tree space:

```text
terminal dimension -> boundary concentration -> log-domain cliffs -> exp overflow -> saturation
```

## What Changed

Forge now has a log-domain optimizer branch in the actual optimizer pipeline.
It is opt-in and analysis-only:

```python
optimize_module(module, log_domain=True, optimizer_trace_path="trace.json")
```

The branch identifies functions whose expression shape is likely to benefit
from positive, exp-mapped search coordinates. It exports an audit trace instead
of rewriting semantics. That is deliberate: log-domain search changes optimizer
coordinates, not the user's mathematical function signature.

Explorer now exposes the evidence packets with drilldown: DAG cost, replay
frames, guard status, packet hash, and JSON export.

MachLib now has a compile-checked high-dimensional theorem queue under
`MachLib.HighDimensional`. One obligation is closed over an explicit
geometric-decay foothold; the remaining items stay marked as theorem targets.

## Why This Matters

Most symbolic optimizers treat tree search as if useful expressions are spread
through the interior. The high-D packets say the opposite: useful, finite,
non-saturated EML behavior is a narrow subset of a search space dominated by
faces, corners, and invalid domains.

That is the strategic reason for the Monogate stack:

- EML gives a uniform one-operator kernel.
- Forge records when search enters domain, overflow, and saturation pressure.
- IR replay packets make the lowering path inspectable.
- MachLib turns the evidence trail into theorem obligations.

This is the path from experimental optimization to verifiable compilation.

## Next Research Target

The next frontier is not a bigger random search. It is a proof-carrying
log-domain search discipline:

```text
positive coordinate transform
  -> guarded EML evaluation
  -> replay packet
  -> MachLib domain-preservation obligation
  -> Explorer audit surface
```

That is the line where EML stops being only a beautiful single-operator trick
and becomes an optimizer architecture for the high-dimensional world.
